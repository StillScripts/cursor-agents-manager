# Convex Better Auth Integration

This document explains how authentication is implemented using Better Auth with Convex as the database backend.

## Overview

The app uses [Better Auth](https://better-auth.com) with the [`@convex-dev/better-auth`](https://labs.convex.dev/better-auth) Convex Component for authentication. This stores all auth data (users, sessions, accounts) in Convex rather than a traditional database.

## Key Files

### Convex Backend

| File | Purpose |
|------|---------|
| `convex/convex.config.ts` | Registers the Better Auth component |
| `convex/auth.config.ts` | Auth provider configuration |
| `convex/auth.ts` | Auth instance with `createAuth()` and `getCurrentUser` query |
| `convex/http.ts` | HTTP router that mounts auth routes |

### Client Side

| File | Purpose |
|------|---------|
| `lib/better-auth/auth-client.ts` | Client-side auth with `convexClient()` plugin |
| `lib/hooks/use-session.ts` | React hook wrapping `useSession()` |
| `components/providers.tsx` | `ConvexBetterAuthProvider` wrapper |

### Server Side

| File | Purpose |
|------|---------|
| `lib/better-auth/auth-server.ts` | Server utilities from `convexBetterAuthNextJs()` |
| `lib/better-auth/session.ts` | Server-side session helpers |
| `proxy.ts` | Next.js 16 proxy for auth redirects |
| `app/(server)/api/auth/[...all]/route.ts` | Auth API route handler |
| `lib/hono/middleware/auth.ts` | Hono middleware for API auth |

## Environment Variables

### Local (.env.local)

```bash
# Convex URLs (auto-generated by `bunx convex dev`)
CONVEX_DEPLOYMENT=dev:your-deployment-name
NEXT_PUBLIC_CONVEX_URL=https://your-deployment.convex.cloud
NEXT_PUBLIC_CONVEX_SITE_URL=https://your-deployment.convex.site
```

### Convex Dashboard (set via CLI)

```bash
# Set these on your Convex deployment
bunx convex env set BETTER_AUTH_SECRET "$(openssl rand -base64 32)"
bunx convex env set SITE_URL "http://localhost:3000"  # or production URL
```

## Data Storage

Auth data is stored in a **Convex Component** namespace, not the main app tables.

To view auth data in the Convex dashboard:
1. Go to the **Data** tab
2. Click the **"app"** dropdown
3. Select **"betterAuth"**
4. You'll see tables: `user`, `session`, `account`, `verification`

## Authentication Flow

### Sign Up / Sign In

1. User submits credentials via `signIn.email()` or `signUp.email()`
2. Request goes to `/api/auth/*` → handled by `auth-server.ts` handler
3. Handler forwards to Convex HTTP routes (`convex/http.ts`)
4. Better Auth validates and creates session in Convex
5. Session token stored in HTTP-only cookie
6. Client receives session data

### Session Validation

1. `proxy.ts` runs on every request (Next.js 16 proxy)
2. Calls `isAuthenticated()` from `auth-server.ts`
3. This queries Convex via `getCurrentUser` query
4. If no session → redirect to `/login`
5. If authenticated → allow request

### API Route Auth

1. Request hits Hono API route
2. `requireAuth` middleware runs
3. Calls `fetchAuthQuery(api.auth.getCurrentUser)`
4. Sets `user` and `session` in Hono context
5. Route handler has access to authenticated user

## Usage Examples

### Client: Check Session

```tsx
"use client"
import { useSession } from "@/lib/hooks/use-session"

function MyComponent() {
  const { user, session, isLoading } = useSession()

  if (isLoading) return <div>Loading...</div>
  if (!user) return <div>Not logged in</div>

  return <div>Hello {user.name}</div>
}
```

### Client: Sign In

```tsx
import { signIn } from "@/lib/better-auth/auth-client"

const result = await signIn.email({
  email: "user@example.com",
  password: "password123",
})
```

### Server: Get Current User

```ts
import { getCurrentSession } from "@/lib/better-auth/session"

export async function getData() {
  const session = await getCurrentSession()
  if (!session) return null

  // session.user.id, session.user.email, etc.
  return fetchDataForUser(session.user.id)
}
```

### Server: Protected API Route (Hono)

```ts
import { requireAuth } from "@/lib/hono/middleware/auth"

app.use("*", requireAuth)

app.get("/", async (c) => {
  const user = c.get("user")
  // user.id, user.email available
})
```

## Hybrid Architecture Note

Currently, the app uses a hybrid approach:
- **Authentication**: Convex (Better Auth)
- **User API Keys**: Still in Drizzle/Turso (not yet migrated)
- **Other user data**: Still in Drizzle/Turso

The `simulation.ts` middleware bridges this by:
1. Getting the authenticated user from Convex
2. Querying Drizzle for their API key using the user ID

## Troubleshooting

### "Unauthorized" redirect loop

- Check that `bunx convex dev` is running
- Verify `NEXT_PUBLIC_CONVEX_URL` and `NEXT_PUBLIC_CONVEX_SITE_URL` are set
- Check Convex dashboard logs for errors

### Session not persisting

- Verify `BETTER_AUTH_SECRET` is set on Convex deployment
- Check that cookies are being set (browser dev tools)
- Ensure `SITE_URL` matches your actual URL

### No data in Convex dashboard

- Auth data is in the **betterAuth** component namespace
- Switch from "app" to "betterAuth" in the dropdown
