# Model: ApiKeys

## Overview
Stores encrypted API keys for users. Each user has one record containing their encrypted Cursor API key and OpenAI API key. Keys are encrypted client-side before storage and decrypted server-side when needed for API calls.

---

## Schema

### Description
Secure storage for user API keys. Keys are encrypted using AES-256-GCM before being stored in the database. Each user has a single record that can contain both Cursor and OpenAI API keys.

### Fields
- `_id`: Id<"apiKeys">  
  Primary key. Auto-generated by Convex.

- `userId`: string  
  References the authenticated user. One record per user.

- `encryptedCursorApiKey`: string  
  Required. AES-256-GCM encrypted Cursor API key. Empty string if not set.

- `encryptedOpenaiApiKey`: string  
  Required. AES-256-GCM encrypted OpenAI API key. Empty string if not set.

---

## Relationships
- One ApiKeys → One User (`userId`)

---

## Indexes & Constraints
- Unique index: `by_user` on `userId`
- Non-null: `userId`, `encryptedCursorApiKey`, `encryptedOpenaiApiKey`
- Validation:
  - Each user can have only one `apiKeys` record
  - Empty strings indicate keys are not set (not deleted)
  - Keys must be encrypted before storage (encryption happens client-side or via actions)
