# Model: Launch Agents

## Overview
Stores records of every agent launch request, including both one-time and recurring job configurations. Launch agents track the configuration used to launch agents via the Cursor API, and can be configured to automatically re-run on a schedule. Recurring jobs are executed by a scheduled cron job that checks for due executions and respects the repeat count limit.

---

## Schema

### Description
Represents a launch agent record that stores the configuration for launching an AI agent. Each record contains the prompt, source repository, model, target settings, and optional recurring job parameters. For recurring jobs, the system tracks execution count, schedules next runs, and automatically deactivates when the repeat count is reached.

### Fields
- `_id`: Id<"launchAgents">  
  Primary key. Auto-generated by Convex.

- `userId`: string  
  Required. References the authenticated user. Launch agent belongs to a user.

- `prompt`: Prompt  
  Required. Agent prompt configuration.
  
  Prompt object structure:
  - `text`: string - Required. The task description/prompt text
  - `images`: Array<Image> | undefined - Optional array of images to include
  
  Image object structure:
  - `data`: string - Base64-encoded image data
  - `dimension`: { width: number, height: number } - Image dimensions

- `source`: Source  
  Required. Repository source configuration.
  
  Source object structure:
  - `repository`: string - Required. GitHub repository URL
  - `ref`: string | undefined - Optional. Git branch/ref (defaults to repository default)

- `model`: string | undefined  
  Optional. AI model identifier to use for the agent.

- `target`: Target | undefined  
  Optional. Target branch and PR configuration.
  
  Target object structure:
  - `autoCreatePr`: boolean - Whether to automatically create a PR
  - `openAsCursorGithubApp`: boolean | undefined - Whether to open as Cursor GitHub App
  - `skipReviewerRequest`: boolean | undefined - Whether to skip reviewer request
  - `branchName`: string | undefined - Target branch name

- `taskId`: Id<"tasks"> | undefined  
  Optional. Associated task ID for organizing launches.

- `recurringJob`: RecurringJob | undefined  
  Optional. Recurring job configuration (only present for recurring jobs).
  
  RecurringJob object structure:
  - `intervalDays`: number - Days between each execution
  - `repeatCount`: number - Total number of times to repeat (including first execution)
  - `currentCount`: number - Current execution count (starts at 1, increments after each execution)
  - `isActive`: boolean - Whether the job is active (false when completed or cancelled)

- `nextRunAt`: number | undefined  
  Optional. Next scheduled execution time in milliseconds since epoch. Only set for recurring jobs. Set to `undefined` when job is complete or inactive.

- `agentId`: string | undefined  
  Optional. The agent ID that was created from this launch (if successful). This is the external agent ID from the Cursor API.

- `createdAt`: number  
  Required. Timestamp (milliseconds) when launch agent record was created.

## Relationships
- Many Launch Agents → One User (`userId`)
- One Launch Agent → One Task (`taskId` in tasks table, optional)
- One Launch Agent → One Agent (`agentId` references external Cursor agent ID)

---

## Indexes & Constraints
- Index: `by_user` on `userId`
- Index: `by_next_run` on `nextRunAt` (used for finding due recurring jobs)
- Index: `by_user_created` on `(userId, createdAt)`
- Non-null: `userId`, `prompt`, `source`, `createdAt`
- Validation:
  - `recurringJob` is only present when job is configured as recurring
  - `nextRunAt` is only set for recurring jobs
  - `currentCount` starts at 1 (first execution already happened when record is created)
  - `isActive` is `true` for active recurring jobs, `false` when completed or cancelled
  - `nextRunAt` is cleared (`undefined`) when recurring job is complete

## Recurring Job Logic

### Execution Flow

1. **Initial Creation** (`create` mutation):
   - When a recurring job is created, `currentCount` is set to `1` (first execution already happened)
   - `nextRunAt` is calculated as `now + intervalDays * 24 * 60 * 60 * 1000`
   - `isActive` is set to `true`

2. **Scheduled Execution** (`checkAndExecuteRecurringJobs` action):
   - Runs hourly via cron job (at the top of every hour)
   - Queries for launch agents where:
     - `nextRunAt <= currentTime`
     - `recurringJob.isActive === true`
     - `nextRunAt` is defined
     - `currentCount < repeatCount` (JavaScript filter)
   - For each due job, calls `executeLaunchAgent`

3. **Job Execution** (`executeLaunchAgent` action):
   - Validates job is still active and conditions are met:
     - `recurringJob.isActive === true`
     - `currentCount < repeatCount`
     - `nextRunAt` is defined
     - `nextRunAt <= currentTime`
   - Launches new agent using stored configuration
   - Creates new launch agent record for this execution
   - Updates original launch agent via `updateLaunchAgentAfterExecution`

4. **Post-Execution Update** (`updateLaunchAgentAfterExecution` mutation):
   - Increments `currentCount` by 1
   - If `currentCount >= repeatCount`:
     - Sets `isActive = false`
     - Clears `nextRunAt` (sets to `undefined`)
   - Otherwise:
     - Calculates next run: `now + intervalDays * 24 * 60 * 60 * 1000`
     - Updates `nextRunAt` with new scheduled time

### Safety Guarantees

The system has multiple layers of protection to ensure jobs only run when appropriate:

1. **Query-Level Filtering**: Filters by time, active status, and `nextRunAt` defined
2. **JavaScript Filtering**: Ensures `currentCount < repeatCount` before including in results
3. **Execution Validation**: Double-checks all conditions in `executeLaunchAgent` before launching
4. **Post-Execution Check**: Verifies and deactivates when limit is reached

This ensures jobs will **ONLY** run when:
- ✅ `nextRunAt <= currentTime` (time is correct)
- ✅ `isActive === true` (job is active)
- ✅ `currentCount < repeatCount` (repeat count is respected)
- ✅ `nextRunAt` is defined (job is scheduled)

## Functions

### Public Functions

#### `create` (mutation)
Creates a new launch agent record. For recurring jobs, initializes the recurring job state and schedules the next run.

**Args:**
- `prompt`: Prompt object
- `source`: Source object
- `model`: string | undefined
- `target`: Target object | undefined
- `taskId`: Id<"tasks"> | undefined
- `recurringJob`: { intervalDays: number, repeatCount: number } | undefined
- `agentId`: string | undefined

**Returns:** `{ _id: Id<"launchAgents"> }`

### Internal Functions

#### `createInternal` (internalMutation)
Internal mutation to create a launch agent record. Used by recurring job execution to create new launch records for each execution.

#### `getLaunchAgentsDueToRun` (internalQuery)
Queries for all launch agents with recurring jobs that are due to run. Filters by time, active status, and repeat count.

**Args:**
- `currentTime`: number (milliseconds since epoch)

**Returns:** Array of launch agent documents that are due to run

#### `getLaunchAgentByIdInternal` (internalQuery)
Gets a launch agent by ID. Used internally by `executeLaunchAgent`.

**Args:**
- `launchAgentId`: Id<"launchAgents">

**Returns:** Launch agent document | undefined

#### `updateLaunchAgentAfterExecution` (internalMutation)
Updates a launch agent's recurring job after execution. Increments `currentCount` and updates `nextRunAt` if more executions remain, or deactivates the job if the repeat count is reached.

**Args:**
- `launchAgentId`: Id<"launchAgents">

**Returns:** `{ success: boolean, currentCount: number }`

#### `executeLaunchAgent` (internalAction)
Executes a recurring job from a launch agent. Launches a new agent using the stored configuration, creates a new launch record, and updates the original launch agent.

**Args:**
- `launchAgentId`: Id<"launchAgents">

**Returns:** `{ success: boolean, agentId: string }`

**Throws:**
- If launch agent not found
- If recurring job is not active
- If repeat count already reached
- If `nextRunAt` is not defined
- If job is not yet due

#### `checkAndExecuteRecurringJobs` (internalAction)
Scheduled function (called by cron job) to check and execute recurring jobs that are due. Runs hourly and processes all due jobs.

**Args:** None

**Returns:** `{ executed: number }` (number of jobs executed)

## Cron Job Configuration

The recurring job executor is configured in `crons.ts`:

```typescript
crons.hourly(
  "check-recurring-jobs",
  {
    minuteUTC: 0, // Run at the top of every hour
  },
  internal.launchAgents.checkAndExecuteRecurringJobs
)
```

This runs every hour at minute 0 (e.g., 1:00, 2:00, 3:00, etc.) to check for and execute due recurring jobs.

## Example Use Cases

### One-Time Launch
```typescript
await ctx.runMutation(api.launchAgents.create, {
  prompt: { text: "Fix all TypeScript errors" },
  source: { repository: "https://github.com/user/repo" },
  model: "claude-3-5-sonnet-20241022",
  agentId: "bc-123..." // Set after agent is launched
})
```

### Recurring Job (Daily for 7 days)
```typescript
await ctx.runMutation(api.launchAgents.create, {
  prompt: { text: "Run test suite and report results" },
  source: { repository: "https://github.com/user/repo", ref: "main" },
  recurringJob: {
    intervalDays: 1,    // Run every day
    repeatCount: 7      // Run 7 times total
  }
})
```

### Recurring Job (Weekly for 4 weeks)
```typescript
await ctx.runMutation(api.launchAgents.create, {
  prompt: { text: "Generate weekly report" },
  source: { repository: "https://github.com/user/repo" },
  recurringJob: {
    intervalDays: 7,   // Run every week
    repeatCount: 4     // Run 4 times total
  }
})
```
