# Model: Work Summaries

## Overview
AI-generated summaries of work sessions. Currently supports daily summaries, but designed to support weekly and monthly summaries in the future. Each summary is generated from time logs and provides insights into productivity, accomplishments, and work patterns.

---

## Schema

### Description
Stores AI-generated summaries of work periods. Initially designed for daily summaries, but the model structure supports future expansion to weekly and monthly summaries. Summaries are generated from time logs and provide a concise overview of work completed during the period.

### Fields
- `_id`: Id<"workSummaries">  
  Primary key. Auto-generated by Convex.

- `userId`: string  
  References the authenticated user. Summary belongs to a user.

- `day`: string  
  Required. Date in readable format (e.g., "January 15, 2024" or "2024-01-15"). Represents the day the summary covers. This field can be extended in the future to support week/month periods.

- `summary`: string  
  Required. The AI-generated summary text describing the work completed during the period.

- `createdAt`: number  
  Required. Timestamp (milliseconds) when summary was created.

---

## Relationships
- Many Work Summaries → One User (`userId`)

---

## Indexes & Constraints
- Index: `by_user` on `userId`
- Index: `by_user_day` on `(userId, day)` - Ensures one summary per user per day
- Non-null: `userId`, `day`, `summary`, `createdAt`
- Validation:
  - `day` must be a valid date string
  - `summary` must be non-empty
  - Each user should have at most one summary per day (enforced by unique index on `(userId, day)`)

---

## Future Considerations
This model is designed to support weekly and monthly summaries in the future. Potential extensions:
- Add `periodType` field: "day" | "week" | "month"
- Rename `day` to `period` to be more generic
- Add additional metadata fields as needed
