# Model: TimeLogs

## Overview
Time tracking entries for user tasks. Each log records when work started and ended on a task. Logs can be active (ongoing, no endTime) or completed. Users can only have one active time log at a time.

---

## Schema

### Description
Tracks time spent on tasks. Each log represents a work session with a start time and optional end time. Active logs (no endTime) represent ongoing work. Users are limited to one active log at a time to prevent overlapping sessions.

### Fields
- `_id`: Id<"timeLogs">  
  Primary key. Auto-generated by Convex.

- `userId`: string  
  References the authenticated user. Time log belongs to a user.

- `taskId`: Id<"tasks">  
  Required. References `Tasks._id`. The task this time log is for.

- `activityType`: string | undefined  
  Optional. Type of activity (e.g., "coding", "review", "debugging").

- `startTime`: number  
  Required. Timestamp (milliseconds) when work started.

- `endTime`: number | undefined  
  Optional. Timestamp (milliseconds) when work ended. `undefined` means the log is active/ongoing.

- `createdAt`: number  
  Required. Timestamp (milliseconds) when log was created.

---

## Relationships
- Many TimeLogs → One User (`userId`)
- Many TimeLogs → One Task (`taskId`)

---

## Indexes & Constraints
- Index: `by_user` on `userId`
- Index: `by_task` on `taskId`
- Index: `by_user_task` on `(userId, taskId)`
- Index: `by_user_created` on `(userId, createdAt)`
- Non-null: `userId`, `taskId`, `startTime`, `createdAt`
- Validation:
  - `endTime` must be after `startTime` if provided
  - Users can only have one active log (one with `endTime === undefined`) at a time
  - `taskId` must reference an existing task that belongs to the user
